Endpoints

GET    /                     the page
GET    /api                  all tracked projects (read token / IP allowlist)
GET    /api/discover         git repos under allowed_roots that aren't tracked yet
POST   /api/projects         { "id": "<sha256 of realpath>", "name": "...", "service": "..." }
DELETE /api/projects/{name}  stop tracking (never touches the repo itself)

Why "add" takes an id and never a path

A path from the network + git = arbitrary filesystem read. So:

1. allowed_roots in config.json is the ONLY source of scannable paths
2. /api/discover returns {id, path} where id = sha256(realpath)
3. POST accepts the id — the server maps it back to the path IT found
4. realpath() resolves symlinks BEFORE the allowed_roots check
5. reject if not a git repo, already tracked, or outside allowed_roots
6. writes require a separate admin token, not the read token
7. config.json is written atomically (tmp + os.replace); every add/remove logged
8. allow_ui_edit = false  -> the whole panel disappears. Recommended on prod.

Status is derived, not stored — the agent decides

no .git / unreadable          -> none  "no git repo"
branch != main_branch         -> bad   "not on main"
process_started < checked_out -> warn  "pulled, not restarted"
behind > behind_warn          -> warn  "N behind"
checked_out older than N days -> bad   "stale (Nd)"
behind unresolvable           -> none  "? unknown"
otherwise                     -> ok    "in sync"
